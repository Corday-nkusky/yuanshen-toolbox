# 更新日志

版本号只有一处权威来源：`app.py` 里的 `APP_VER`。窗口标题、日志和 exe 的
「文件属性 → 详细信息」都来自它（`build.cmd` 打包前调用 `make_version_info.py`
生成 VERSIONINFO，再通过 PyInstaller 的 `--version-file` 写入）。
**exe 文件名固定为 `YuanshenToolbox.exe`，不带版本号**，详见 `docs/BUILD.md`。

## 版本号规则

从 v0.12.0 起按这个口径递增（1.0 之前固定 `0.MINOR.PATCH`）：

- **PATCH**：修 bug、文案、性能、内部重构；不新增能力，也不改变已有数据口径。
  （例：v0.11.1 修复站点改版导致的「网站已有」失效。）
- **MINOR**：新增能力，或用户需要知道的行为变化 —— 新页签、新数据源、新上传范围、
  数据目录 / PB 口径变化、删功能。1.0 之前的破坏性变更也走 MINOR，并在本文件写明。
  （例：v0.12.0 并入网站 PB、把 PB 改成两张榜。）
- **MAJOR**：1.0.0 及以后的不兼容变更。0.x 阶段不使用 MAJOR。

同一批改动里既有修复又有新功能时，按最高一级算。只有准备发出去的 exe 才递增一次版本号，
本地源码调试不占版本号；发版时只改 `APP_VER`，把 `## 未发布` 改成 `## vX.Y.Z`。
已发布过的版本号不复用，哪怕只是「重打一次包」。

## v0.26.0

**每日页多了 stnb 三列；某一天的成绩可以一键复制成文本或图片发出去。**

- 每日页加 stnb 的最高 / 平均 / 最低三列，与时间、3BV/s 一样按「三列一组」在表头上
  标出组名。13 列的设计宽度压在 880 以内 —— Tk 的 Treeview 只会把多出来的宽度摊给
  各列，窗口拉窄时**不会**自动缩列，超了就直接截掉右边，所以宁可一开始就窄。
- 每日页**右键某一天**：「复制当日总结（文本）」和「复制当日总结（图片）」。
  文本是几行紧凑的纯文字（日期 / 级别 / 局数 / 起止 / NF / 三项指标 / 版本），
  图片是一张浅色卡片，2 倍像素渲染，字体用程序自带的 MiSans。
- 概览页「最近完成局」右上角加**今日总结**按钮：把今天有局的级别（有一个算一个）
  并到一段文字 / 一张图里。不出一行「合计」—— 三级的 BV 分布不同，
  把它们的平均时间再平均一次没有意义，合计局数放在标题右边。
- 图片直接进剪贴板（CF_DIB，ctypes 直调 Win32，不引 pywin32）。64 位下必须声明
  `argtypes`：HGLOBAL 是指针宽度，按默认 int 传会把句柄截断，轻则失败重则崩进程。
- 每日页默认看**高级**，并且三个级别按钮里那一个真的点亮了。以前默认画的是初级，
  但按钮全灰着，看不出当前在哪一级。
- `--selftest` 的回执多一行 `summary_png=宽x高`：打包后少打 PIL 或字体时，
  这一行会变成 `ERR`，不用等到发图才发现。

## v0.25.0

**新增「每日」页：按天看每天打了多少局、成绩分布如何。**

- 第 6 个页签「每日」，一天一行：局数、起止时刻，以及时间的最快 / 平均 / 最慢、
  3BV/s 的最高 / 平均 / 最低。中间那列是**算术平均**（与 Arbiter 的 Daily Review 同口径）。
  一屏之外滚动即可，不做「近 30 天 / 90 天」筛选 —— 有局的日子最多几百行，
  而"从哪天开始练、总共多少天"本身就是最该看见的信息。
- 归日按**那一局开始的时刻**，跨午夜的算在开始那天（本机 22723 局里只有十几局）。
- 双击某一天（或点「当天明细」）弹出当天每一局：时刻 / time / BV / 3BV/s / stnb /
  风格 / 距当前 PB，双击某一局用元扫雷播放。
- 时间改成读**录像头里的时间戳**，不再是文件修改时间。以前「日期」一列其实恒等于
  mtime —— 拷贝、解压过的录像会全落在同一天。现在概览「最近完成局」的日期与时间、
  PB 详情、CSV 导出里的日期都跟着变准。
- `.avf`（阿比特）存的是「当时的本地墙钟被当成 UTC 编码」，`.evf`（元扫雷）存真 UTC。
  读取时统一归一化成真本地时间；对 avf 直接用 `fromtimestamp` 会整整偏 +8 小时，
  21 点以后打的局会被算到第二天，而界面上看不出任何异常 —— 所以有两个写死期望日期的
  单测守着。
- 老缓存里没有时间字段，升级后第一次扫描会就地补全并写回：本机 23183 局 **30 秒**，
  状态栏写一句「补齐 N 局录像时间」，之后不再出现。

## v0.20.2

**自动上传不动、状态栏卡在「正在扫描…99%」、前端成绩不更新。**

- 自动上传补上「第二拍」：新录像要等 1.5 秒写稳才判定，而判定原本只在扫描结束
  时跑一次，扫描又只在有文件变化时发生 —— 一局打完之后没有第二拍，于是自动上传
  要等到下一局落地、或者用户手点「立即检查」才动。现在只要有局在等写稳，1.5 秒
  后会自己再判一次。
- 状态栏不再卡在「正在扫描…已读 22400 / 22555（99%）」：自动上传会把「开传前
  那一行」存下来，若那一刻底下还挂着扫描进度，传完还原的就是一句早已作废的进度，
  而且会一直挂着。现在进度行属于一次性消息，也不会被当成还原目标；扫描结论改为
  先写、再交给自动上传。
- 自动上传成功后重读站点数据（前端成绩 / 网站 PB /「网站已有」）。以前只有手动
  上传那条路末尾会刷新，自动传上去的涨分局在界面上还是旧数据，看着像没传上去。
- 解析前先核对录像文件头：ms-toollib 读到全零 / 垃圾内容时不是抛异常，而是让整个
  进程直接消失（实测 64 字节全零的 .evf 必崩，Python 侧抓不到）。本机全量核过
  270 个 .evf（首字节 0x04、第三字节 0x40）与 7198 个 .avf（首字节 0x34），对不上
  的一律按「读不出」处理，不再送进去。
- 新增 `test_auto_flow.py`（10 项）：第二拍、状态栏还原、传完刷新、坏文件拦截。

- 自动刷新复选框去掉「目录时间戳」这种实现细节。
- 选目录的窗口标题只留「选择录像目录」，删掉与弹窗重复的括号补充。
- 修「录像目录」窗口高度写死导致底部说明被切掉：窗口原先是固定的 760×492（逻辑像素），

## v0.20.0

**exe 文件名固定，升级不再需要重发桌面快捷方式。**

- 以前每版 exe 都叫 `YuanshenToolbox-v<版本号>.exe`，文件名一变，桌面快捷方式就指向一个

  副本。旧 exe 正在运行也能升级 —— Windows 不允许覆盖运行中的文件，但允许把它改名挪走，
  脚本先挪后写，下次双击就是新版。
- 部署目录与 `dist\` 仍然各自只留一个 exe。

## v0.19.1

**口径变化：只统计标准模式。**

- 无猜（竞速 / 强 / 弱 / 准）、强可猜、弱可猜、win7、upk、标准递归、自定义盘面，这些录像
  从此一条都不进统计、也不参与上传（手动和自动都不传）。
- 元扫雷 `.evf` 按**文件名第二段**判：那一段就是 mode（`b_0_1.774_…` 里的 `0`），只有 `0`
  算标准；自定义盘面是 `c_` 前缀，整条跳过。这一条任何时候都准，且不花额外时间。
- 阿比特 `.avf` 按**录像内容**判：`level = 6` 是自定义盘面（老缓存里这个信息也在），
  `mode ≠ 0` 是变体玩法。阿比特本身没有无猜玩法，实测 23183 条录像 mode 全是 0，
  所以**不为老缓存补这个字段重新解析** —— 那会让打开工具箱多等十几秒。
- 扫描结束那行会写「跳过 N 个非标准局」；一条都没有时不显示。
- 依据：mode 编码出自 openms 站点源码 `back_end/saolei/config/text_choices.py`，
  文件命名出自元扫雷 `src/app/game_engine.py` 的 `cal_evf_filename`。

新增 `test_mode.py`（16 项）：八种变体 mode 逐个验证被跳过、自定义前缀被跳过、
标准局与没打完的局计数不受影响。实测本机 22525 个文件全部标准，扫描仍 0.4 秒。

## 0.8.1

- **同一局存了多份时只算一局**（统计与上传列表都不再出现重复行）。两种来源：
  阿比特破纪录时会额外导出一份 `HI-SCORE *.avf`，与它 `replays` 目录里的正本逐字节相同；
  归档子目录（如整包下载的 `gsc\27415gsc16`）也常与 `replays` 各存一份。
  本机 `D:\扫雷` 因此从 23,106 局修正为 **22,371 局**（去掉 735 份副本），磁盘文件不动。
- 判重**只认文件字节**：阿比特录像的时间只有 10 ms 精度，同级别 / 同 BV / 同时间的不同局
  大量存在（实测 `(b, 3, 970)` 三份里有两份 bv、rce、solved 全同，`left` 4 vs 5、点击流
  111 vs 404 事件，是两局不同的游戏）。按指标合并会误删真局，所以不做指标级去重。
- 只对「大小 + 级别 + BV + 时间」四项都撞上的候选组算 md5 —— 实测占全量 6.4%，
  首扫多 1 秒左右；哈希按 `(路径, mtime, size)` 记进 `scan-cache.db` 的 `file_sha` 表，
  之后回到 1 秒内。清空缓存会把哈希一起清掉。
- 保留规则：文件名不带 `HI-SCORE` 优先 → 目录层级浅优先 → 路径字典序。
  不用 mtime（换机器结果就变）。所以双击复制到的是正本路径，上传用的也是正本。
- 界面上不体现这件事（状态栏「文件数 → 局数」就是去重后的数字），只在日志里记一行
  「去掉重复副本 N」。
