# 更新日志

版本号只有一处权威来源：`app.py` 里的 `APP_VER`。窗口标题、日志和 exe 的
「文件属性 → 详细信息」都来自它（`build.cmd` 打包前调用 `make_version_info.py`
生成 VERSIONINFO，再通过 PyInstaller 的 `--version-file` 写入）。

## v0.11.2

- **上传前二次确认**：新建 `UploadConfirmDialog`，用同一套粉紫配色 + 药丸按钮 + 同款表格
  列出本批的级别/风格/来源/time/BV/大小/文件名，并给出级别构成与合计大小。
  「上传选中」「上传全部未传」「重试失败」三个入口都要过一次确认；Esc 取消、回车确认。
  超过 400 条只列前 400 条并注明「其余 N 个同样会上传」，避免建几万个 Treeview 行。
  文件名列按最长文件名自动量宽（上限 560），不再截成「…Corday(Tongcheng).e」。
- **上传页按范围过滤**：选中范围 Pill 后，表格只显示该范围的录像（含已上传的），
  不再把上万局全铺在表里。`up_rows` 仍是全集，逻辑判断不受影响；
  统计行同时给「本地总数 / 当前范围行数（待传）」，按钮上的数字也改成当前范围的计数。
- 上传列表项新增 `level` / `size`（字节），供确认框排序与合计大小使用。

## v0.11.1

- **修复「网站已有」判定失效**：站点后端改版后 `/api/userprofile/videolist` 不再返回
  `timems` / `bv` / `file_size`，只剩 `id / player / upload_time / state`，于是程序拿不到
  去重三元组，所有录像都被当成「未上传」。现在改成两步：先取 ID 列表，再用
  `/api/video/staticdetailbatch` 按 100 个一片批量补齐解析字段（该接口单次上限就是 100，
  超了回 400；限流 5 次/秒，所以每片间隔 0.25 s）。遇到 429/5xx 按 1s→2s→3s 退避重试。
  拿不到明细的少数录像不再静默跳过，状态栏会写「其中 N 条缺少明细，按未上传处理」。

- **exe 写入 VERSIONINFO**：文件属性里现在能看到 FileVersion / ProductVersion、
  产品名、描述和版权；版本号由 `APP_VER` 自动注入，不需要手改第二处。
- 仓库清理：取消跟踪运行期缓存 `scan-cache.db`（文件仍留在本地），`.gitignore`
  改认 `元神工具箱-data/`；测试脚本去掉写死的本机路径；README 修正路径笔误和
  「数据目录固定叫」的措辞。
- **老测试可判定**：`test_smoke.py` / `test_upload.py` 改成退出码判定（扫描、PB 筛选/搜索/排序、
  Top5 渲染、选范围/全选/表格同步），`test_upload.py` 默认用临时数据目录、不碰真实账号；
  `test_tabs.py` 明确为截图工具，找不到窗口或截图为空时退出 1。
- **首页减负**：删掉表格下方整行 PB 口径说明；`record.ini` 对账改成只在发现「仅 ini 有」
  或「数值冲突」时提示，正常/没有 record.ini 时结果只写日志，不再占状态栏右下角。
  README 预览图同步换成 v0.11.0 的截图。
- **录像额度提示**：站点超限时返回空的 HTTP 402；程序据此停批，并提示用户联系网站
  管理员增加录像额度，不再在提示里写死具体条数。
- **健壮性修补**：数据目录写探测不再因为「目录已存在」而跳过（只读位置会正确回落到
  `%APPDATA%`）；重试耗尽的 429/5xx 按临时失败计入连续失败，连续 3 条即停批；
  上传期间禁用退出登录 / 重扫 / 换目录，避免剩余上传全变 403 或表格错位；
  缓存目录不可写时降级为不缓存继续扫描；上传台账写盘失败不再残留临时文件；
  没有保存会话时启动不再发匿名请求。

## 0.8.1

- **同一局存了多份时只算一局**（统计与上传列表都不再出现重复行）。两种来源：
  阿比特破纪录时会额外导出一份 `HI-SCORE *.avf`，与它 `replays` 目录里的正本逐字节相同；
  归档子目录（如整包下载的 `gsc\27415gsc16`）也常与 `replays` 各存一份。
  本机 `D:\扫雷` 因此从 23,106 局修正为 **22,371 局**（去掉 735 份副本），磁盘文件不动。
- 判重**只认文件字节**：阿比特录像的时间只有 10 ms 精度，同级别 / 同 BV / 同时间的不同局
  大量存在（实测 `(b, 3, 970)` 三份里有两份 bv、rce、solved 全同，`left` 4 vs 5、点击流
  111 vs 404 事件，是两局不同的游戏）。按指标合并会误删真局，所以不做指标级去重。
- 只对「大小 + 级别 + BV + 时间」四项都撞上的候选组算 md5 —— 实测占全量 6.4%，
  首扫多 1 秒左右；哈希按 `(路径, mtime, size)` 记进 `scan-cache.db` 的 `file_sha` 表，
  之后回到 1 秒内。清空缓存会把哈希一起清掉。
- 保留规则：文件名不带 `HI-SCORE` 优先 → 目录层级浅优先 → 路径字典序。
  不用 mtime（换机器结果就变）。所以双击复制到的是正本路径，上传用的也是正本。
- 界面上不体现这件事（状态栏「文件数 → 局数」就是去重后的数字），只在日志里记一行
  「去掉重复副本 N」。

## 0.8.0

- **支持阿比特（Arbiter）`.avf` 录像**：和元扫雷 `.evf` 一起扫描、一起算 PB / 前端成绩。
  阿比特的级别 / 时间 / BV 一律以**录像内容**为准，不看文件名（阿比特的文件名是
  另一个程序另写的，规则不统一，有的还带 `HI-SCORE` 前缀或不带 3BV）。
- **多目录**：新增「路径 (N)…」按钮，可以加任意多个录像文件夹（replay、阿比特存档、
  移动硬盘备份…），每个能单独「启用 / 停用」，停用的不参与扫描。都收在 `config.json`
  的 `roots` 里，旧版本的单个 `root` 自动升级。没有新增页签。
- **阿比特上传可选**：上传页「范围」行加了「含阿比特录像」勾选框（默认勾上）。
  取消后上传列表里只留元扫雷的局；勾选框旁边写着被排除了多少个。
- 上传列表加了「来源」列（元扫雷 / 阿比特）。
- 去重键优先用录像里的整数毫秒（`rtime_ms`），不再用 `round(秒×1000)`，
  避免 ±1 ms 误差导致「网站已有」判不出来、白传一次。
- `record.ini` 对账只用元扫雷的局 —— record.ini 本来就是元扫雷写的，
  混进阿比特只会多出一堆必然对不上的「数值冲突」。
- 命令行 `--root` 可以写多次，一次指定多个目录。
- **扫描缓存**（`scan-cache.db`，数据目录内）：按 (mtime, 大小) 记住每局录像解析出来的
  rce / BV / 时间 / 标识，没变就不再重演。实测 23,183 个阿比特录像：
  首次 173.5 s → 缓存后 **0.9 s**（缓存库 8 MB）。诊断窗口里可以「清空缓存」。

## 0.7.0

- **断点续传**：新增上传台账 `uploads.json`（数据目录内），每成功一条就记下去重键。
  断网/崩溃/关程序后重开，即使还没联网拉到网站列表，也不会把已传的当成「未上传」
  （显示「已传过（本地记录）」）；一旦拿到网站列表则以服务器为准。
- **单条失败不再拖垮整批**：上传内部对网络错误按 1s → 2s → 4s 退避重试，
  `503` 与新增的 `429`（限流）听 `Retry-After`；重试耗尽记为「失败」继续下一条。
  只有账号级错误（403 / 402 / 未实名 / 封禁）才停整批。
- **网络连续 3 条失败自动停批**，避免白等 N 个 90 秒超时。
- 新增「重试失败 (N)」按钮：只补传上一批失败的条目，已成功的不动。
- 账号行显示本地台账条数。
