# 「这一局涨了多少分」怎么做

> 目标：概览页「最近完成局」里，让涨了分的局显示 `+2.8`。
> 状态：**已实现**（`core.lsf_gains` + 概览页那一列）。本文留作依据与边界说明。
> 事实分级：**【实测】**= 在你的 23,394 局真实数据上跑出来的；**【源码】**= 读 `core.py` 得出。

## 1. 结论

**不用做实时记录。** 按录像时间顺序把历史重放一遍，就能算出每一局在当时涨了多少分，
和"当时记下来"是同一个数。代价是 0.05 秒（两段式），不需要每局落盘。

## 2. 为什么能事后算

涨分的定义是一局的**边际贡献**：

```
涨分(i) = LSF(前 i 局) - LSF(前 i-1 局)
```

LSF 只由 18 项前五均值决定（`core.lsf_soft`），而"前 i 局"完全由录像集合决定 ——
录像文件带着 mtime，排序就能还原"那一刻我有哪些成绩"。

一个恒等式可以当校验：把所有局的涨分加起来，必然等于当前的 LSF。
【实测】23,394 局复算，总和 2838.9，与末态 LSF 2838.9 分毫不差。

实测分布（你的数据）：

| 项 | 值 |
| --- | --- |
| 涨分 > 0.05 的局 | 821 / 23,394（3.5%） |
| 单局涨幅中位数 | +1.56 |
| 单局涨幅最大 | +82.3（前几个 BV 在填前五的空位） |
| 最近 500 局里涨分次数 | 2 |

## 3. 真正会漂的两件事

涨分是三个量的函数：**这一局之前的全部成绩**、**锚点**（全站前 20 名的水平）、
BV 门槛（常量）。后两个里，只有锚点会动。

### 3.1 锚点（尺子会变）

软实力是 `100 × A / V`（时间）和 `100 × V / A`（3BV/s），A 就是锚点。
A 变了，同一局算出来的涨分按比例变 —— 这不是 bug，是"尺子换了"。

现在 `lsf-anchors.json` 只留最新一份，历史没档。所以**要"当时涨了多少"，就得留档**：
每次锚点变动往同一个文件里追加一份 `{时刻, 12 个数}`，一年也就变几十次、几 KB。
复算第 i 局时用它 mtime 之前最近的一份，数字就锁死在"当时那把尺子"上。

不想要这个语义也行（永远用当前锚点），那就连档都不用留，代价是老的涨分数字会跟着站点整体水平慢慢漂。

### 3.2 只在网站上、本地没有的成绩

`core.lsf_top5` 会把网站 Top5 并进来（`merge_top_rows`），而站点给的是**现在**的 Top5，
不是历史的，这部分无法回溯。

【实测】你的页面口径 LSF 和纯本地口径 LSF 完全相同（2792.8 = 2792.8），
说明网站那 18 个小榜里没有任何一条是本地没有的。只要你的成绩都在本机，
这一项就是 0，可以不理会。

真到了"在别人机器上打、只在网站有"的地步，再给这些局补一个落盘的小账本也不迟。

## 4. 算法：两段式

窗口（"最近完成局"那 100～2000 行）之外的局，只影响**起点状态**，而起点状态与顺序无关
（前五只看集合），所以一次遍历就够；窗口内才需要按顺序走。

```
state = core._lsf_heaps(窗口之前的全部局)        # 一次遍历
for g in 窗口内按 mtime 升序:
    before = lsf(state, anchors_at(g.mtime))
    push(state, g)
    delta[g] = lsf(state, anchors_at(g.mtime)) - before
```

【实测】23,394 局：一段 0.04 s + 窗口 100 局 0.01 s = **0.05 s**，
与全量顺序复算（2.20 s）逐局比对，最大差 `0.000000000`。

放在后台线程，扫描完成后算一次，缓存到内存；录像数或锚点变了才重算。

**已实现**：`core.lsf_gains(games, anchors, rows)` → `{path: 涨分}`。
实测 200 局 0.068 s（含起点那一遍 2.3 万局），与全量顺序复算逐局一致（差 0）。
界面里按 `(录像列表, 行数, 锚点)` 缓存，一次扫描只算一遍。

## 5. 边界情况

- **批量导入**：解压来的录像 mtime 全是同一秒，顺序无意义。现在的判据：
  窗口内大于 5 局、且不同 mtime 少于 3 个，就算不出先后，整列不显示。
- **录像被删 / 改名**：历史状态会变，涨分跟着变。这是"复算"的固有性质，
  落盘账本反而会出现"账上有、实际没有"的鬼数据。
- **NF 只占 0.03**：NF 局同时进 std 和 nf 两个桶，但 nf 权重只有 3%，
  所以 NF 局涨分通常很小。这是权重，不是算错。

## 6. 界面上怎么放

- 「最近完成局」最后一列「涨分」，右对齐，值形如 `+2.8`；不是涨分局就留空。
- **整屏没有涨分局时，这一列连表头一起收掉**（`Table.set_hidden` 用
  `displaycolumns` 藏列）。涨分本来就稀有，留一列 96% 空白的表头是白占地方。
- 它和「距当前 PB」是两个参照系：后者以**现在**为基准，前者以**当时**为基准。
- **涨分与 PB 无关**：没破 PB 的局，只要挤进某一项前五，一样涨分。
  实测窗口里就有这种局（初级 BV10 1.590 s，比该 BV 的 PB 慢，涨 +1.3）。
- **【实测】破 PB 的 2,024 局里，76% 一分不涨。** 破 PB 但没挤进该 BV 那一项的前五
  就不涨分，所以"有 PB、涨分空着"是常态。不额外标注 —— 涨分只在真涨的时候出现。

## 7. 已经定下来的

1. **阈值**：> 0.05 算涨，显示 `+0.1` 起。（不写 0.0）
2. **锚点**：先用当前锚点（不留历史档）。数字会跟着站点整体水平慢慢漂，
   要不要锁"当时那把尺子"以后再说。
3. **不标"破 PB 但没涨分"**：那是常态，标出来只会把 76% 的行铺满噪声。
