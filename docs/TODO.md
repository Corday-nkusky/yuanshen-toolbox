## 已知边界（不算 bug，但要知道）

- **重复副本判重靠字节相同**。阿比特若改格式，让 `HI-SCORE *.avf` 与正本字节不同，就抓不到
  （那时得改成比对点击流签名，成本高一个量级）。当前 479 个 HI-SCORE 里 395 个的孪生字节全同。
- **阿比特文件名解析只覆盖实测写法**（`HI-SCORE ` 前缀、`_NF_`/`_FL_`、`#Exp_`、`Beg_1.00_3BV=6_...`）。
  `玩家名在前` 那种（`Ju Ze En_Exp_26.1(3bv123).avf`）解析不出，靠录像内容兜底 —— 也因此
  「无法解析」计数里可能出现其实是正常的文件。
- **扫描目录上限 20000 个子目录**，到顶截断并在状态栏说明；正常 replay 目录不会触发。
- **扫描缓存不做孤儿行剪枝**：删掉的录像会在 `scan-cache.db` 里留行（不影响结果，只是库慢慢变大）。
- **带比赛编号的标识要先登记**：打比赛产生的录像（元扫雷、阿比特都一样）标识后面会带
  比赛编号（如 `玩家名(地区) G18248`）。这种完整标识若没在账号「标识管理」里登记，
  上传会成功但 `state=d`（标识不匹配、不进榜）。程序只能提前标红，不能代登记。
- **`record.ini` 对账只覆盖元扫雷**：那份文件是元扫雷写的，阿比特的成绩没有第二来源可校准。
- **「手动添加 = 全是你自己的」是约定，不是校验**：程序只能靠目录边界判断归属，加进来的目录
  里若混着别人打的录像，仍会计入 PB 并进上传列表。没有做「按 `player_identifier` 白名单过滤」
  —— 同一个人在不同软件不同时期的标识写法实测能变出八九种（拼写、大小写、地区、编号、有没有
  括号都不一样），白名单会误杀自己；而下载来的录像里那个名字字段是可以被本地 profile 改写或
  冒用的，也不能当证据。
- **首扫时长取决于录像条数**：2 万局、冷缓存约 3 分钟（`read_video` 逐局重演），
  有进度条但不是能加速的东西。缓存命中后 1 秒出头。

## 每次发版前的手工验收

1. `python test_arb.py`、`python test_resume_ui.py`、`python test_retry.py`、
   `python test_smoke.py`、`python test_upload.py` 退出码都是 0
   （`test_tabs.py` 是截图工具，不参与回归判定）。
2. `build.cmd` → 覆盖 `%APPDATA%\Metasweeper3.3.4\元神工具箱.exe` → `--probe` → 日志里
   `启动 vX.Y.Z` 与 `APP_VER` 一致；文件属性 → 详细信息里的 FileVersion 也一致。
3. 真机开一次：概览 / PB / 前端成绩 / 上传四页各看一眼（行高、对齐、滚动条）。
4. 有账号时确认「网站已有 N」与站点实际条数一致（去重键没漂）。
