## 0. 一句话

v0.28 的详细版是「同一组数换个排版」；v2 要做成**一天的复盘卡**：
先把这一天和**自己的历史**对齐（不是和别人的绝对值对齐），再给一张能看出「哪一局好在哪、差在哪」的
**BV × 用时散点**，最后给两张名单——**该骄傲的五局**和**该回看的五局**。

### 2.2 一条新约束（这次实测出来的）

工作簿的 29 列 CSV 里，`ce / cl / op / is / path` 是**录像重演的产物**（网站抓的点击流），
所以它能算「每秒有效点击」「路径移速」「IOE」。我拿本机 355 条录像试 ms-toollib：

```
25/25 条元扫雷录像：v.ce = 0, v.cl = 0, v.path = 0.0, v.thrp = 0
                   但 v.op / v.isl 正常，kp.lce / kp.left / kp.dce / kp.flag 正常
```

结论：**点击效率三件套（ce/s、corr、路径移速）现在拿不到**，能拿到的是
`left（左键总数）/ lce（有效左键）/ dce（双击）/ op（开荒点击）/ isl（孤立点击）`。
要用得先扩 `scan()` 的缓存字段，属于**另一件事**，不进 v2（见 §7）。

### 2.3 一个别照抄的细节

Sub 页的「稀有度话术」（基操 / 强局 / 量产 / 惊喜 / 突然 / 发财 / 狗运）落档规则是
`pct × 2^k > 100` 就取第 k 档，而注释写的是「基操 1/8~」。**代码实际比注释低一档**
（12.5% 会落进「强局」而不是「基操」）。想搬这套话术就自己定义边界，别抄它的档位。

### 3.1 头部（沿用）

日期 + 级别 chip（只有一级时）+ 总局数 + 起止/FL/NF 一行小字。
**小字仍然只有「起止 + FL + NF」**，不算跨度（这是硬红线，测试里钉着）。

### 3.2 摘要行（新增，2~3 行，12 px 灰）

每个级别一行，只写**事实**，不写形容词：

```
中级 42 局 · 日均 stnb 72.5（历史最高）· 14 局进全期前 50（最好第 1）
```

- 日均 stnb 的百分位见 §3.4 的口径；到顶/到底时改写「历史最高 / 历史最低」。
- 「进全期前 50」= 该级别、过 3BV 门槛的历史全部局按用时排序的前 50 名里，今天占几局、最好第几。
  这一项没有任何阈值需要维护（50 是 Arbiter 的默认 `rklist`，也可改成与「Top 榜」页一致）。
- 为什么要这一段：手机竖屏上大部分人只会读最上面三行，这三行必须能独立成话。

### 3.3 级别头 + 「前五局 / 巅峰」（新增）

- 左：级别 chip、局数、起止、FL/NF。
- 右：`全期最好 stnb 96.4（11-17）` —— 这个级别的天花板。**用 stnb 而不是时间**，因为 stnb 已经按
  盘面归一，跨 BV 可比；时间 PB 通常来自小盘，写出来会误导。
- 第二行：`前五局 大雷神 4.9　软实力 64.0 · et 52.5 s` + 右侧 `巅峰 大雷神 9.0`。
  - 取值：当天该级别**最好的五局**（Time 升序 / 3BV/s 降序 / stnb 降序），不足五局按「最差」补满
    （`core._lsf_mean` 的既有口径，与梁山分卡片完全一致）。
  - 软实力与定阶直接调 `core.lsf_report(当日局, anchors=本地锚点)`，**不新写公式**。
  - 锚点读 `YuanshenToolbox-data/lsf-anchors.json`（和梁山分卡片是同一份快照）；读不到就整行不出。
  - **注意读法**：当天的前五局必然是历史前五局的子集或更差，所以「前五局 ≤ 巅峰」是结构性的，
    不是退步。文案用「巅峰」而不是「全期」，就是为了避免被读成「我今天变菜了」。

### 3.4 三列对照表（改造）

| 今天 | 近 30 天 | 最好的一天 |
| --- | --- | --- |

- **今天** = 当日算术平均（与 `daily_rows` 同口径，不另算）。
- **近 30 天** = 该级别过去 30 天（不含今天）**所有局**的平均，按局加权，
  不是「日均再平均」——后者会让只打 3 局的日子和打 80 局的日子同权。
- **最好的一天** = 该级别历史日均 stnb 最高的那天（含三项：那天的时间/3BV/s/stnb 平均）。
  比的是「日子」而不是「单局」，因为今天也是一个日子。
- 三个指标仍是 时间 / 3BV/s / stnb（与总结卡一致，不新增指标，避免两张卡对不上）。
- 没有可比历史（第一次打这个级别）时退化成单列大字，不摆一排「—」。

### 3.5 BV × 用时散点（新增，核心图）

- 横轴 = 这一天的 3BV 范围（两侧各留 5%）；纵轴 = 用时，**左下角标最小值、左上角标最大值**
  （数字放在绘图区外的留白里，点上的标注永远不会压到它）。
- 点 = 每一局，淡色；**当日最快那一局**实心大点 + 标注用时。
- 虚线 = **该 BV 的历史中位用时**（按 ±1 个 BV 再取一次中位做平滑）。
  线上方 = 比平时慢，线下方 = 比平时快。为什么不用 PB 曲线见 §4.2。
- 标题行右侧：`今天刷新 N 个 BV 纪录`（该 BV 历史至少 3 局才算数，否则「第一次打这个 BV」也叫纪录）。
- 高度 108 px（8~14 局时降到 100），单日 40 局大约 0.02 s 出图。

### 3.6 用时分布（保留但降级）

- 8 个等宽桶，柱顶写局数；标题行右侧给 `中位 x.xx s　最快 x.xx s`。
- **不画 PB 竖线**：PB 通常就落在最小桶的边上，画出来是一条压在柱子上的线，没增加信息。
- 只在 ≥15 局时出现。

### 3.7 节奏（替换「前半程/后半程」两行）

按时间把当天切成 4 段（按局数均分，不是按钟点均分——深夜 20 分钟刷 15 局和白天 6 小时打 12 局，
按钟点切会切出「3 局一段」这种没法看的行）：

```
01:13 起　10 局　均 17.448 s　stnb 71.8
02:10 起　10 局　均 17.610 s　stnb 73.9　+2.0
```

- 比快慢**用 stnb 不用时间**：段与段之间的 BV 分布不同，时间直接比不公平（§4.1 同一个道理）。
- 最右一列是「与上一段的 stnb 差」，涨用级别色、跌用灰（不引入红绿，避免和涨跌语义打架）。

### 3.8 双榜（重做）

| 左：最快 5 局（≥ 门槛 BV） | 右：离自己 PB 最远 5 局 |
| --- | --- |
| `11.168　36 BV　NF` | `+21%　17.207 s　53 BV　NF` |

- 左边加 **3BV 门槛**（初 10 / 中 30 / 高 100，即 `core.BV_MIN_DEFAULT`），
  过门槛的局不足 3 局时退回全部并在标题里去掉门槛说明。没有门槛的「最快 5 局」永远是刷小盘。
- 右边是 **slow = 用时 ÷ 该 BV 自己的历史最快**，取最慢的 5 局。
  这就是「该回看的五局」：BV 差异被 PB 除掉了，剩下的只有「这一盘我打得有多散」。
  百分比比绝对秒数好读，也跨 BV 可比。

### 3.9 口径脚注（新增，3 行 9.5 px）

```
P = 今天的日均 stnb 在自己该级别的所有「有局的日子」里的百分位；
最好的一天 = 该级别日均 stnb 最高的那天；离 PB 最远 = 用时 ÷ 同 BV 历史最快。
前五局 = 当天最好五局按站点锚点算的软实力与定阶；巅峰 = 历史最好五局的同口径值。
```

理由：这张卡里有四个「自造口径」，不写清楚就会变成「你算错了」。用户的习惯是先质疑口径，
脚注就是把口径提前摆出来。

### 3.10 退化规则（必须实现，否则小日子会出一堆空标题）

| 当日该级别局数 | 出什么 |
| --- | --- |
| ≥ 15 | 全部：散点 + 分布 + 节奏 + 双榜 |
| 8 ~ 14 | 散点（高 100）+ 「全部 N 局」逐条列表 |
| 1 ~ 7 | 只出「这一天的每一局」逐条列表（无分布无趋势，列表就是最详细的版本） |
| 该级别无历史可对比 | 对照表退化成单列大字，不出「近 30 天 / 最好的一天」 |
| 锚点文件缺失 | 「前五局 / 巅峰」整行不出，其余照常 |

实测高度：2 局的一天 1136×1712；42 局单级别 1136×2590；82 局双级别 1136×3954；49 局三级 1136×3918。

## 4. 三个口径决定

### 4.1 「该复盘的局」不能按 stnb 最低选

stnb = 常数 × bv / t^1.7。bv 进分子，t 在 1.7 次方上，所以**小盘的 stnb 天然低**：
19 BV 的 6.052 s 得 32.05，53 BV 的 17.207 s 得 40.9。按 stnb 排序选出来的「后五名」几乎就是
「bv 最小的五局」，跟推得好不好没关系——v0.28 就是这么选错的。

改成 `slow = 用时 ÷ 同 BV 历史最快`：把「这一盘该打多久」除掉，剩下的才是我自己的问题。
这条同时解决了「分段比较」和「双榜排序」两个地方。

**补一句必要的旧账**：v0.28.0 当时是把「最慢 5 局」和「离 PB 最远」一起否掉的，
理由是「慢常常只是盘大，stnb 低才是推得乱」。这个理由对**绝对用时**完全成立，
但对 `slow` 不成立——它已经被同 BV 的 PB 除过了，「盘大」这个因素在分母上就消掉了；
反过来 stnb 恰恰是最受 bv 影响的那个量（bv 直接进分子），所以当年那个替代方案
是拿一个受 bv 影响的量去修另一个受 bv 影响的量。三条量纲摆在一起：

| 量 | 受盘面大小影响 | 能不能跨 BV 比 |
| --- | --- | --- |
| 用时 t | 强（≈ 线性） | 不能 |
| stnb | 强（bv 在分子，但 t^1.7 补偿过度，小盘系统性偏低） | 不能，方向还反了 |
| slow = t / PB(BV) | 一阶已消（PB 本身随 BV 变） | 能，量纲是「倍数」 |

所以这不是推翻当时的判断，而是当时缺一个「除完盘面」的量——`slow` 才是那个量。

### 4.2 参考线用中位，不用 PB

PB 曲线是每个 BV 各自的最快，相邻 BV 之间没有任何连续性，连起来是一排锯齿（原型第一版就是
这样，31 个点配一条锯齿线，看着像故障）。中位是「这个盘面我平时打多久」，本身连续，
再按 ±1 BV 平滑一次就是一条能当基准的线：**线上方慢、线下方快**，一眼能读。
PB 不浪费——它变成右榜的除数。

### 4.3 「前五局 / 巅峰」怎么读

它是**同一把尺子的两个高度**：尺子 = 站点锚点（`lsf-anchors.json`），高度 = 五局口径的软实力。
当天的五局一定不比历史五局好，所以这个数字永远 ≤ 巅峰，它的意义是「今天离自己的天花板差多少」。
不是「今天退步了」——这句话必须靠文案和脚注兜住，否则每天都会被读成退步。

## 5. 与 v0.28 逐项对照

| --- | --- | --- |

## 7. 刻意没做的

| 工作簿里的东西 | 为什么不进 v2 |
| --- | --- |
| 定阶九档 + 「犬牢」（`arr81`） | 站点口径只到「外星人」，`core.LSF_GRADE_CN` 也只有九档。加第十档就是自造体系，和梁山分卡片对不上。 |
| 炸局按进度外推（`est = 双击时刻 × 3BV / 已完成 3BV`） | `scan()` 现在把未完成局整条丢掉（`core.py` 里 `if not vid["completed"]: continue`）。要用得先决定「未完成局算不算一局」，会动到所有局数口径，不能顺手做。 |
| 点击效率（ce/s、corr、thrp、路径移速） | 元扫雷录像上这些字段全是 0（§2.2），要用得扩缓存字段。值得做，但单独一件。 |
| 周 T37 / 月 Top / 年 Top | 日粒度凑不齐；那是「最近 100 局」或「本月」视图该干的事。 |
| 染色收集（230 格） | 依赖「BV × 名次」的格子体系，我们没有。 |
| 狗图概率外推（1.55 / 2.3 / 3.8） | 常数是手调的，工作簿里没有任何拟合依据（研究笔记 §4.3 已记）。 |
| Sub 页那套稀有度话术 | 档位边界和注释对不上（§2.3）；要用就自己定义，别挂「照抄 Arbiter」的名。 |

## 8. 成本

- 渲染：82 局双级别 0.22 s（含一次全量 `lsf_report`）、42 局单级别 0.02 s。开图不卡。
- 计算：全部 O(总局数)，一次 `scan()` 后无需重新读盘。
- 代码量：`summary.py` 约 +380 行（含注释），`app.py` 约 +10 行，测试 +150 行。
- 高度：单级别 ~2590 px（约 2.3 屏）、双级别 ~3950 px（约 3.6 屏）、三级 ~3900 px。
  **这是本方案唯一的风险点**：如果觉得太长，第一刀砍「节奏」，第二刀砍「用时分布」，
  两处合计约 220 px/级别。
